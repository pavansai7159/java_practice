Data Structures & Algorithms

Critical core concepts heavily tested in initial rounds.

🟢 Easy

1. Two Sum

Problem: Given an array of integers nums and an integer target, return indices of the two numbers such that they add up to target.

public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> map = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];
        if (map.containsKey(complement)) {
            return new int[] { map.get(complement), i };
        }
        map.put(nums[i], i);
    }
    throw new IllegalArgumentException("No match found");
}

2. Contains Duplicate

Problem: Given an integer array nums, return true if any value appears at least twice.

public boolean containsDuplicate(int[] nums) {
    Set<Integer> set = new HashSet<>();
    for(int i : nums){
        if(!set.add(i)) return true;
    }
    return false;
}

3. Best Time to Buy and Sell Stock

Problem: You are given an array prices where prices[i] is the price of a given stock on the ith day. Maximize your profit by choosing a single day to buy one stock and choosing a different day in the future to sell that stock.

public int maxProfit(int[] prices) {
    int minPrice = Integer.MAX_VALUE;
    int maxProfit = 0;
    for (int p : prices) {
        if (p < minPrice) minPrice = p;
        else if (p - minPrice > maxProfit) maxProfit = p - minPrice;
    }
    return maxProfit;
}

4. Valid Anagram

Problem: Given two strings s and t, return true if t is an anagram of s, and false otherwise.

public boolean isAnagram(String s, String t) {
    if (s.length() != t.length()) return false;
    int[] store = new int[26];
    for (int i = 0; i < s.length(); i++) {
        store[s.charAt(i) - 'a']++;
        store[t.charAt(i) - 'a']--;
    }
    for (int n : store) if (n != 0) return false;
    return true;
}

5. Merge Two Sorted Lists

Problem: Merge two sorted linked lists and return it as a sorted list.

public ListNode mergeTwoLists(ListNode list1, ListNode list2) {
    ListNode dummy = new ListNode(-1);
    ListNode tail = dummy;
    while(list1 != null && list2 != null) {
        if(list1.val < list2.val) { tail.next = list1; list1 = list1.next; }
        else { tail.next = list2; list2 = list2.next; }
        tail = tail.next;
    }
    tail.next = (list1 != null) ? list1 : list2;
    return dummy.next;
}

🟡 Medium

1. LRU Cache (High Frequency)

Problem: Design a data structure that follows the constraints of a Least Recently Used (LRU) cache.

Solution: Use a HashMap paired with a Doubly Linked List.

class LRUCache {
    class Node { int key, val; Node prev, next; Node(int k, int v) { key = k; val = v; } }
    Node head = new Node(-1, -1), tail = new Node(-1, -1);
    Map<Integer, Node> map = new HashMap<>();
    int capacity;
    
    public LRUCache(int capacity) {
        this.capacity = capacity;
        head.next = tail; tail.prev = head;
    }
    private void add(Node node) {
        Node next = head.next; head.next = node; node.prev = head; node.next = next; next.prev = node;
    }
    private void remove(Node node) {
        Node prev = node.prev, next = node.next; prev.next = next; next.prev = prev;
    }
    public int get(int key) {
        if (!map.containsKey(key)) return -1;
        Node node = map.get(key);
        remove(node); add(node);
        return node.val;
    }
    public void put(int key, int value) {
        if (map.containsKey(key)) remove(map.get(key));
        Node node = new Node(key, value);
        map.put(key, node); add(node);
        if (map.size() > capacity) {
            Node lru = tail.prev; remove(lru); map.remove(lru.key);
        }
    }
}

2. Number of Islands

Problem: Given an m x n 2D binary grid grid which represents a map of '1's (land) and '0's (water), return the number of islands. Use DFS or BFS to traverse adjacent lands.

public int numIslands(char[][] grid) {
    if (grid == null || grid.length == 0) return 0;
    int count = 0;
    for (int i=0; i<grid.length; i++) {
        for (int j=0; j<grid[0].length; j++) {
            if (grid[i][j] == '1') {
                count++; dfs(grid, i, j);
            }
        }
    }
    return count;
}
private void dfs(char[][] grid, int r, int c) {
    if (r<0 || r>=grid.length || c<0 || c>=grid[0].length || grid[r][c] == '0') return;
    grid[r][c] = '0';
    dfs(grid, r+1, c); dfs(grid, r-1, c); dfs(grid, r, c+1); dfs(grid, r, c-1);
}

3. Coin Change

Problem: You are given an integer array coins representing coins of different denominations and an integer amount. Return the fewest number of coins that you need to make up that amount.

public int coinChange(int[] coins, int amount) {
    int max = amount + 1;
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, max);
    dp[0] = 0;
    for(int i=1; i<=amount; i++) {
        for(int coin : coins) {
            if(coin <= i) {
                dp[i] = Math.min(dp[i], dp[i - coin] + 1);
            }
        }
    }
    return dp[amount] > amount ? -1 : dp[amount];
}

4. Kth Largest Element in an Array

Problem: Given an integer array nums and an integer k, return the `k`th largest element in the array.

public int findKthLargest(int[] nums, int k) {
    PriorityQueue<Integer> minHeap = new PriorityQueue<>();
    for (int num : nums) {
        minHeap.add(num);
        if (minHeap.size() > k) minHeap.poll();
    }
    return minHeap.peek();
}

🔴 Hard

1. Trapping Rain Water

Problem: Given n non-negative integers representing an elevation map where the width of each bar is 1, compute how much water it can trap after raining.

public int trap(int[] height) {
    if (height == null || height.length == 0) return 0;
    int left = 0, right = height.length - 1;
    int maxLeft = 0, maxRight = 0, res = 0;
    while(left < right) {
        if(height[left] <= height[right]) {
            if(height[left] >= maxLeft) maxLeft = height[left];
            else res += maxLeft - height[left];
            left++;
        } else {
            if(height[right] >= maxRight) maxRight = height[right];
            else res += maxRight - height[right];
            right--;
        }
    }
    return res;
}

2. Merge k Sorted Lists

Problem: You are given an array of k linked-lists, each list is sorted in ascending order. Merge all the linked-lists into one sorted list.

public ListNode mergeKLists(ListNode[] lists) {
    PriorityQueue<ListNode> pq = new PriorityQueue<>((a, b) -> a.val - b.val);
    for (ListNode node : lists) {
        if (node != null) pq.add(node);
    }
    ListNode dummy = new ListNode(0);
    ListNode tail = dummy;
    while (!pq.isEmpty()) {
        tail.next = pq.poll();
        tail = tail.next;
        if (tail.next != null) pq.add(tail.next);
    }
    return dummy.next;
}

3. Median of Two Sorted Arrays

Problem: Given two sorted arrays nums1 and nums2 of size m and n respectively, return the median of the two sorted arrays. The overall run time complexity should be O(log (m+n)).

public double findMedianSortedArrays(int[] nums1, int[] nums2) {
    if(nums1.length > nums2.length) return findMedianSortedArrays(nums2, nums1);
    int m = nums1.length;
    int n = nums2.length;
    int low = 0, high = m;
    while(low <= high) {
        int partitionX = (low + high) / 2;
        int partitionY = (m + n + 1) / 2 - partitionX;
        int maxLeftX = (partitionX == 0) ? Integer.MIN_VALUE : nums1[partitionX - 1];
        int minRightX = (partitionX == m) ? Integer.MAX_VALUE : nums1[partitionX];
        int maxLeftY = (partitionY == 0) ? Integer.MIN_VALUE : nums2[partitionY - 1];
        int minRightY = (partitionY == n) ? Integer.MAX_VALUE : nums2[partitionY];
        
        if (maxLeftX <= minRightY && maxLeftY <= minRightX) {
            if ((m + n) % 2 == 0) return ((Math.max(maxLeftX, maxLeftY) + Math.min(minRightX, minRightY)) / 2.0);
            else return Math.max(maxLeftX, maxLeftY);
        } else if (maxLeftX > minRightY) high = partitionX - 1;
        else low = partitionX + 1;
    }
    throw new IllegalArgumentException();
}

System Design (HLD & LLD)

Expect questions spanning LLD (Design Patterns) to HLD (Scalability Architecture).

🟢 Foundational

1. What is the difference between Load Balancers and API Gateways?

Load Balancer: Operates primarily at OSI Layer 4 or 7. Distributes traffic across instances based on algorithms (Round Robin, Least Connections). Examples: AWS ALB, Nginx.

API Gateway: Sits deeper in the application logic. Handles routing, authentication/authorization, rate limiting, request/response transformation, and metrics logging. Examples: AWS API Gateway, Kong, Apigee.

2. Explain the Singleton and Factory Design Patterns (LLD).

Singleton: Ensure only one instance of a class exists across the application. Used for Config managers or DB Connection pools. (Always mention Thread-Safe Double Checked Locking strategy).

Factory: Provides an interface for creating objects in a superclass, but allows subclasses to alter the type of objects that will be created.

🟡 Medium / LLD Heavy

1. Design a Rate Limiter

Algorithms: Token Bucket, Leaky Bucket, Fixed Window Counter, Sliding Window Log, Sliding Window Counter.

Implementation Strategy: Use Redis (In-memory datastore). Use Lua scripts in Redis to make read-and-decrement actions atomic. Handle distributed rate limiting per user IP, or Customer ID.

2. Design a URL Shortener (Bitly)

Core Challenge: Avoiding collision and scale (Millions of writes, billions of reads).

Strategy: Base62 Encoding. To prevent collision across distributed nodes, use Apache Zookeeper to give ticket-ranges to generation servers, or use a standalone ID Generator database.

Storage: Key-Value store (Cassandra, DynamoDB). Read-heavy so heavy caching via Redis is required.

3. Low Level Design: Design a Parking Lot

Key Classes: ParkingLot, ParkingFloor, ParkingSpot (Compact, Large, Handicapped), Vehicle, Ticket, PaymentTerminal.

Patterns to use: Strategy Pattern for dynamic pricing per hour. Factory to generate standard vs EV spots. State pattern (Occupied, Free, Reserved).

🔴 Advanced / HLD Architecture

1. Design a Payment Gateway / Processing System

Critical Focus: ACID Transactions, Idempotency, No single point of failure (SPOF).

Architecture:

  • Requests hit the API Gateway.
  • Pass to a Payment Executor Service.
  • All states MUST be stored in an ACID compliant DB (PostgreSQL). State transitions: INITIATED -> PROCESSING -> SUCCESS/FAILED.
  • To ensure Idempotency, every transaction must have a unique UUID (Idempotency Key). If a retry with the same UUID hits the API, return the previous state rather than double parsing.
  • If a downstream Bank API fails or times out, use Kafka queues with Dead Letter Queues (DLQ) for asynchronous retry mechanisms.

2. Design a Distributed Message Queue (like Kafka)

Components: Producers, Consumers, Brokers, Zookeeper (or KRaft for cluster metadata management).

Storage Strategy: Store messages in append-only immutable files (segments) per topic partition. To keep it fast, rely heavily on OS Page Cache rather than JVM Heap. Zero-copy operations to send data directly from disk buffer to network socket.

Java & Spring Boot

Core JPMC tech stack. Deep understanding of JVM, concurrency, and Spring internals required.

🟢 Easy

1. Differences between Abstract Class and Interface in Java 8+?

Interfaces can now have default and static methods. However, Abstract classes can hold state (instance variables), while Interfaces cannot. A class can implement multiple interfaces but only extend one abstract class.

2. What are the Spring Bean Scopes?

  • Singleton (default): One instance per Spring IoC container.
  • Prototype: New instance every time it is requested.
  • Request, Session, GlobalSession (Web-aware only).

3. How does Garbage Collection work?

Generational GC splits Heap into minor/young generation (Eden, Survivor spaces) and major/old generation. Minor GC cleans Eden fast. PermGen (Java 7) became Metaspace (Java 8). Popular GCs: G1GC (default in newer Javas), ZGC (Ultra low latency).

🟡 Medium

1. How does Spring Boot AutoConfiguration work?

Driven by the @EnableAutoConfiguration annotation (which is part of @SpringBootApplication). It looks at the classpath for specific jars and defaults. Validations rely heavily on @ConditionalOnClass or @ConditionalOnMissingBean to spin up beans automatically.

2. Explain Volatile vs Synchronized in Java concurrency.

volatile ensures memory visibility (reads from main memory instead of CPU cache) but does NOT ensure atomicity (i++ is not safe). synchronized locks the object/block, ensuring only one thread executes it, providing both visibility and atomicity.

3. Explain the internal working of Java 8 Streams.

Pipelines consist of a source, intermediate operations (lazy, e.g., map, filter) and a terminal operation (e.g., collect, forEach). Execution doesn't start until the terminal operation is invoked. Operates mostly in a pull-architecture via Spliterator.

🔴 Hard

1. ThreadPoolExecutor Architecture & Tuning

If a thread pool has core pool size 5, max pool size 10, and queue capacity of 50. What happens at 6 concurrent tasks?

Answer: Request 1-5 consume core threads. Request 6 gets added to the queue. A new thread (up to maxPoolSize) is ONLY created if the queue becomes full (task 56).

2. How to prevent Memory Leaks in Java?

Even with GC, objects referenced by static Maps/Lists will never be collected. Fix: Use WeakHashMap. Don't leave database Connections, Streams, or Sockets open; always use Try-With-Resources. Close ThreadLocal variables.

3. How does Spring AOP work under the hood?

Spring AOP uses JDK dynamic proxies (if an interface exists) or CGLIB proxies (if subclassing is required) to wrap target beans at runtime. When a method is invoked, it flows through the advice chain (Before, After, Around) before hitting the target bean.

Databases: Redis, ES, MongoDB, SQL

🟡 Intermediate & Concept based

1. Differences between clustered index vs non-clustered index?

Clustered index defines the physical order of data in a table (Primary Key default). Only 1 per table. Non-clustered index creates a separate B-Tree holding pointers to the actual data location. You can have many non-clustered indexes.

2. How does Elasticsearch score documents? (TF-IDF vs BM25)

Term Frequency (TF) asks how often a word appears in a doc. Inverse Document Frequency (IDF) asks how rare the word is across all docs. ES moved to BM25 in version 5.x, which adds saturation (preventing very long documents from dominating results simply because of repeated terms).

3. Redis Persistence strategies?

RDB (Redis Database Backup): Snapshots at specified intervals. Faster, but risks data loss since the last snapshot.

AOF (Append Only File): Logs every write operation. More durable, but leads to large files affecting restart time.

🔴 Advanced Scaling DB

1. Explain Database Sharding and Consistent Hashing

Sharding: Splitting large tables horizontally across multiple DB servers. Challenge: Resharding when scaling up.

Consistent Hashing: Avoids moving a massive amount of records when adding/removing a server node. Instead of id % total_servers, map both servers and data keys onto a virtual hash ring (0-360 deg). Look clockwise to find the server node. Only K/N keys need moving on scale events.

2. Dealing with the "Thundering Herd" or Cache Stampede.

Occurs when an expensive-to-compute cache key expires, and 5000 concurrent requests suddenly bypass cache to hit the DB, crashing it.

Solution: Lock generation strategy. Let only 1 request hit the DB to rebuild cache; force the other 4999 to wait/block, or return a slightly stale value while building cache asynchronously.

DevOps, Docker, Kubernetes & Cloud

🟡 Medium

1. Explain Docker Networking Modes.

  • bridge: default, creates a private network internal to the host.
  • host: removes network isolation; uses the host's networking stack directly.
  • none: completely disables networking stack.

2. Kubernetes High Availability and Self-Healing.

K8s utilizes a Master node consisting of an API Server, etcd, Scheduler, and Controller Manager. Worker nodes run Kubelets. Self-healing is achieved via ReplicaSets ensuring the desired state of Pods is strictly maintained. If a worker node dies, the Controller immediately schedules the pods on functioning nodes.

🔴 Hard

1. Kubernetes Liveness vs Readiness vs Startup Probes.

  • Readiness Probe: Determines if a Pod is ready to accept traffic. If it fails, traffic isn't routed to it, but it isn't killed. Used for apps initializing heavy caches on startup.
  • Liveness Probe: Checks if a Pod is deadlocked. If it fails, Kubelet kills the pod and restarts it.
  • Startup Probe: Disables Liveness/Readiness probes until the app has successfully started.

2. Blue-Green vs Canary Deployments in CI/CD.

Blue-Green: Two identical environments. Traffic routes fully to Green while Blue is upgraded. If Blue is stable, switch router to hit Blue instantly. Fast rollback.

Canary: Route 5% of traffic to the new version. Monitor error rates. If successful, gradully increase to 10%, 50%, 100%. Highly safe.

Kafka & Security (JPMC Focus)

🟡 Kafka & Messaging Medium

1. RabbitMQ vs Kafka.

RabbitMQ: Smart broker, dumb consumer model. Tracks message state. Messages deleted when picked up. Advanced routing.

Kafka: Dumb broker, smart consumer model. Highly scalable appended event log. Great for replayability, stream processing, high throughput log aggregation.

2. JWT (JSON Web Tokens) vs Session Authentication.

Session: Stateful. Server stores session ID in memory/DB. Hard to scale horizontally without sticky-sessions or Redis centralization.

JWT: Stateless. Server signs a payload. To verify, server only needs the secret key. Easy horizontal scaling.

🔴 Security & Networking Hard

1. Implementing RBAC effectively in Microservices.

1. API Gateway validates raw JWT signature. 2. Extracts Roles (e.g., ADMIN). 3. Gateway injects headers downwards into internal services. 4. In Spring Boot, use @PreAuthorize("hasRole('ADMIN')") on controller methods.

2. What is Post-Quantum Cryptography (PQC)?

Symmetric encryption (AES-256) is generally safe from Quantum computers. Asymmetric (RSA, ECC) relies on factoring prime numbers—a task Shor's algorithm running on a quantum computer could do cleanly. PQC refers to adopting mathematical problems (like lattice-based math) that are incredibly difficult for both classical and quantum computers to solve. Essential knowledge for modern banking infrastructure.

Python Capabilities

🟡 Python Medium to Hard

1. Explain GIL (Global Interpreter Lock) in Python.

The GIL ensures that only one native thread executes Python bytecodes at a time, making CPython thread-safe. However, it severely bottlenecks CPU-bound multithreaded applications. To truly bypass the GIL and achieve parallelism in Python for CPU-heavy tasks, you must use the multiprocessing module instead of threading.

2. Generators vs Iterators vs Decorators.

  • Iterator: Object implementing __iter__() and __next__().
  • Generator: A function using yield instead of `return`. It pauses state. Highly memory efficient for massive data streams.
  • Decorator: Higher-order function that takes a function and extends its behavior without modifying it explicitly (Used identically to Spring AOP).
